# NFT protocol cost authorization

Source implementation remains required. This amendment preserves the existing platform-fee contract rather than changing its meaning. No runtime gates have run.

NftFeeQuote and NftFeeAuthorization continue to authorize only the platform fee. A separate NftProtocolCostQuote and authorization bind chain expenditure: physical network identity, original actor and payer wallet/address, request/lifecycle identity, stage and standard, metadata hash, retained rent, non-refundable protocol levy, network fee ceiling, expiration and provider policy evidence. Categories are separate and cannot subsidize one another. A quote is informational until its exact digest and ceilings are accepted and persisted in the lifecycle command.

The initial required implementation is Solana metadata-bearing Create. Ordinary NFTs include mint rent, payer-funded ATA, metadata and master-edition costs; credentials omit master edition but retain mint, initial holding ATA and metadata costs. Later recipient acceptance uses a separate recipient-authorized quote, never issuer consent reconstructed as recipient consent. Every quoted account address and payer is derived from the original command. Existing platform fee remains an independent transfer leg and authorization.

A quote endpoint resolves actual authenticated actor/tenant and wallets, validates the same mint draft and idempotency identity as admission, and calls the provider without custody or signing. The quote endpoint persists an immutable server-issued receipt under an opaque quote ID, including its original expiry and exact actor/tenant/request/draft binding. The mint endpoint loads that selected receipt and validates current authoritative economics and policy against its saved evidence and independent ceilings before atomic lifecycle admission. It must not regenerate a timestamp or nonce and compare the resulting new quote digest. Fresh admission checks expiry at database time in the same transaction as lifecycle creation. An admitted operation preparing later retains its original policy and caps; expiry alone does not invalidate its historical authority or trigger a requote. The original admitted quote is persisted in the lifecycle command; replay returns that original command before mutable quote checks. Quote JSON supplied by a caller is never trusted as provider evidence. An expired quote cannot admit new work; already-admitted exact-wire recovery continues under the original immutable authority.

Solana uses the shared reviewed metadata creation policy and an independently pinned immutable opcode3 cost guard. The quote freezes exact Rent bytes, canonical metadata executable hash/source revision, mint/ATA/metadata/edition allocation costs and nonrefundable levy. The signed transaction includes the guard before creation and the complete fixed instruction grammar. Preparation must reject changed policy or insufficient original category ceilings before custody. Actual fee-for-message and packet checks use the exact unsigned message before signing. Recovered signed bytes never adopt a new blockhash, price, destination or metadata. Expired/no-effect replacement requires explicit new quote authorization and the existing generation proof.

Implementation seams: add typed protocol-cost contracts and validation; provider quote capability and Solana implementation; extend mint command/request/view without altering platform fee identity; add authenticated draft quote route and SDK contract; retain exact accepted quote at admission and thread it to provider preparation; add saved-request UI and explicit replacement authorization. New contract fields on old persisted operations must not silently invent consent; recover their already-prepared wire or require an explicit migration/reauthorization command for unprepared effects.

Acceptance evidence: no custody on quote; changing any actor/payer/network/request/stage/metadata field invalidates authorization; unknown program/source or changed Rent refuses; mint/ATA/metadata/edition and levy have distinct covered amounts; below-cap category does not subsidize another; ordinary NFT and credential differ correctly; recipient acceptance cannot use issuer authority; response-loss replay preserves the original accepted quote and exact wire; generation replacement cannot silently increase cost; real opcode3 execution and complete transaction packet/compute constraints. Provider, domain, SDK and UI fixtures precede the one final integrated sweep.

Independent plan review accepted the persisted-receipt correction. Initial source slice now contains typed cost receipt/authorization, canonical binding validation, immutable keyed Surreal storage, and unit/integration fixtures. Lifecycle admission, provider economics/guard adoption, routes, SDK/UI and generation reauthorization remain required. No gates have run; this slice is not registered or advertised as a complete capability.

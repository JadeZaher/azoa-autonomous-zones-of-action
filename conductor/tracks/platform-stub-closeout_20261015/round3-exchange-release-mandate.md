# Automatic release of a settled exchange purchase

Root independently accepted this exact scope and source-fence mapping before implementation. Runtime and subsequent source review remain separate gates.

This supplies the remaining source-specific automatic-release composition from
the accepted Hold economic cutover. It does not reinterpret an AutoRelease
boolean as permission. The existing immutable source request gains an exact
server-authored release disclosure and separately acknowledged hash, including
recipient wallet, physical asset, quantity, time window and independent network,
locked-balance and nonrefundable-cost caps. Quote and consent are persisted before
the source can consume reserve capacity or sign its exchange funds group.

The actual tenant API-key principal must explicitly carry transfer:sign for this
future custody release as well as swap:sign for the original purchase. Capture a
separate SigningConsentWitness with transfer:sign from that same original
credential; selected authenticated scope ceilings cannot be widened by a newer
row. The participant's original exact UserExplicit swap grant and wallet remain
part of the source authority. Neither a fabricated child credential nor a
historical successful grant receipt establishes these permissions.

Compose mandate creation with the existing HoldLocalCommandPlan opening,
reserve mutation, source consumption and immutable receipt in one transaction.
The source stores the accepted mandate identity. The mandate stores an immutable
exchange-source reference with exact source intent hash, opening receipt ID/hash
and original two-party authority. A source-specific execution fence requires the
permanent Confirmed settlement receipt and Completed source, plus exact active
Hold/mandate binding and current original authority. It cannot treat Committed,
Submitted or ExpiredAbsent as settled. The release still uses the ordinary exact
mandate quote/recipient/cost checks and authorized-wire lifecycle; no recipient
acceptance signature is manufactured by the worker.

The original AutoRelease disclosure cannot change while a source is in flight.
Expired unaccepted disclosure permits an explicit same-key quote revision through
a versioned source request receipt before commitment; a saved ambiguous acceptance
must be reconciled or retired under the same source CAS before replacement. A
committed source retains original terms. Its current authority may be renewed
only through an explicit audited exact-operation authorization, preserving
original immutable witnesses and preventing terminal mandate resurrection.

Finalized exchange accounting does not require current permission. No-effect
compensation atomically closes the unopened mandate alongside liability return;
unknown wire remains blocked. Active treasury closure or user offboarding cannot
erase a confirmed receipt, and cannot itself create permission to release funds.

Required source fixtures cover missing transfer scope, changed disclosure,
quote expiry/acceptance race, commitment rollback without mandate, unresolved
source blocking release, settled source permitting exact release, original
participant or API-key revocation before egress, and no-effect compensation
closing the exact mandate once. No runtime gates run before the integrated sweep.

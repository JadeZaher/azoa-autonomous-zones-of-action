# Replacement of a resolved recovery child

A new separately funded recovery remains a child of the original deployment. The parent link is replaced atomically, never cleared. The old child keeps its immutable request, prepared-history evidence, fees and receipts and gains a permanent ReplacedByOperationId seal. The new child records ReplacesOperationId. Ordinary stage mutations reject sealed children.

Replacement uses two explicit proof variants. ResolvedFailure requires the current child to be Failed, without any prepared or submission-authorized wire, with nonempty fully resolved history containing only FailedOnChain or ExpiredNoEffect. The service re-observes every exact prior wire through its original provider/intent and requires the same final no-business-effect verdict before both quote and admission. Pending, unknown, confirmed cleanup and unobserved signed candidates exclude replacement. NeverAuthorizedRetirement is distinct from expiry: the store must prove no generation was ever submission-authorized. Its initial implementation requires generation zero, empty history, no authorization, and an explicit pre-submission state. A prepared candidate can then be sealed by CAS because signed bytes were never exported and every provider egress path requires the domain first-send CAS. Any ambiguous historical state requires exact wire reconciliation instead. Store fixtures must reject a current false authorization flag when earlier history contains an authorized generation.

The recovery quote's intent binds a NativeRecoveryPredecessor containing old child ID, version, intent hash and canonical history hash, alongside the existing original parent version and intent. The old child's preceding replacement chain is preserved through immutable ReplacesOperationId links. Each predecessor was sealed only after authoritative no-effect evidence; the current failed child is re-observed before replacement. Ancestry traversal is bounded per page with a persisted cursor and validated sealed ancestry digest; cycle detection rejects corruption. There is no lifetime retry limit that would strand a buffer. Every replacement retains the immediate immutable predecessor, and prior finalized evidence is auditable through the linked history.

One transaction checks the exact parent version/history/request, current linked child identity/binding, old child version/request/history/proof-variant/no-projection/no-replacement state, exact server quote with database-clock expiry, and matching actor/tenant/artifact. It seals the old child, swaps the parent link/binding and creates the new child, or rolls all changes back. Current-child continuation, completion, competing replacement and stale parent mutation cannot also win.

The original budget and business instructions never change. The new payer and explicit additional cap are disclosed and authorized separately. Old network fees remain visible through retained child receipts. Existing request-key replay still returns its original child even after replacement, but may not advance a sealed child. Confirmed replacement projects cleanup evidence without overwriting the original resource effect.

The API/SDK/UI continue using quote/start with an explicitly displayed predecessor and new consent. Readonly refresh never signs. Withdrawal of a replacement quote must use a dedicated parent/child-aware CAS because ordinary parent Update is forbidden with a child; it must preserve the child link and current child state, pin the quoted predecessor version/history and compete with continuation and replacement atomically. Runtime fixtures must cover replacement-versus-resume/completion, two competing replacements, changed predecessor evidence and lost-response replay. All checks remain scheduled for the final integrated sweep.

# Round 3 required implementation waves

This plan reconciles both independent Round 3 assessments and the bounded Round 2 handoffs. Both assessments agree the existing architecture is reusable and the listed domain gaps require implementation. It is not implementation approval until independent adversarial plan review findings are resolved. No implementation-size deferrals. Runtime tests remain reserved until the end of Round 4.

## Shared contracts before parallel code

Extend the existing canonical frozen action operation envelope and current authority fence. Persist immutable intent, exact authority, quote/budget/network/artifact identity and prepared wire before any egress. An admitted/submitted result is pending; a successor requires authoritative terminal evidence. Replays resolve the original domain record before current mutable admission gates. New stages require the specific authority and budget already consented to; ambiguity cannot create another generation.

Every protocol lane writes its concrete protocol contract and official source evidence before implementation. Another lane/root reviews it. Shared interfaces, schema model changes and Program registration receive explicit ownership to avoid concurrent rewrites. Actual external protocol limitations must be proven by current official evidence and narrowly represented in capability discovery; a local fixture cannot imply a deprecated public protocol route works.

## Adversarial assessment reconciliation

Both independent assessments are now complete. Their overlapping DEX, WTT, handler, compensation and cleanup findings reinforce the packages above; neither offers evidence for new external deferrals. Additional acceptance requirements:

- Compensation must expose a per-run audited resolution journey; the existing per-node retry endpoint cannot wake or resolve the compensation gate. Define each domain's reversible, pending and irrevocably retained effects. Explicitly authorized retention with authoritative receipts may terminate as retained/partially settled, never falsely claim rollback. No operator assertion can release possibly-sent value.
- Workflow request renewal requires a durable original-key status/cancel-before-admission transaction that also fences delayed first requests. A fresh preview or generic HTTP failure is not proof of non-admission. The UI must read the original admitted run when present, and obtain fresh consent only after authoritative rejected/cancelled proof.
- DEX uses durable actor/wallet/network/asset/amount/expiry/quote identity; the current memory quote cache and ignored idempotency parameter are not an admission mechanism. Verify the current Jupiter endpoint and schema against official docs. Distinguish build-only APIs from actual economic execution across direct and action surfaces.
- Fungible registration and Holon linking are retryable idempotent projections of the exact finalized creation receipt. Pending tx IDs must never enter asset identity fields, reserve registration or completed-operation results.
- Produce a final route/provider/SDK/UI capability matrix for all advertised features and three chains. Base-class extension refusals, honest protocol restrictions, test mocks and input placeholders are not automatically product stubs. Conversely, replacing a false success with an indefinite refusal is not closure.
- Advance/signal original-message retry and same-key changed payload semantics need end-to-end coverage alongside start request persistence. Local browser key retention does not replace server-side discovery and immutable domain identity.

### Preparation and first-send authority (R2)

Preparation keys are domain-separated `(logical operation, stage, generation, immutable intent hash)` and reuse the existing signer nonce/exact-wire journals. The logical actor, asset owner/effect signer, participant and fee payer are distinct bound roles. The domain store atomically persists first-send authorization with its current action authority fence before provider submission. Recovery may observe or rebroadcast only that already authorized exact wire; it cannot collect a new participant signature. Generation replacement needs authoritative final/no-effect proof, an audited state transition and applicable budget/participant consent. A timeout, expired quote or absent RPC result never supplies that proof. Concurrent signer operations and cancel/first-send races are required real-store/protocol fixtures.

### Protocol detail gates (R3–R4)

DEX amendment must name the exact current Jupiter API/IDL instruction variants and route grammar, address-table resolution rules, token accounts/mints/owners, all writable accounts, fee/compute instructions and allowed authority changes. A program allowlist alone is insufficient. Unknown instructions, appended wire, substituted lookup tables and unbound transfers are rejected before signing. The Ethereum baseline is a pinned Uniswap V3-style exact-input single-pool router contract with explicit router/version/pool fee and standard ERC-20 semantics; the author must verify the actual chosen router ABI/deployments and local fixture before source. Any expanded routing grammar needs the same review. No unbounded token approval is implied. Tinyman contract pins validator app, pool, current fee/reserves and genesis. Quotes bind exact-in/out mode, all integer amounts/limits/assets, fees, payer/recipient, expiry and dust/refund semantics. Expiry gates new admission only. Approval/opt-in prerequisite effects remain recorded and recoverable if the swap fails. Unsupported token mechanics appear as precise capability constraints, never ordinary successful settlement.

`round3-bridge-contract-input.md` is normative for C's package. C owns asset attestation/wrapped registration, target account creation/opt-in, recipient/payer/rent and guardian transport/set rotation as explicit stages, not future refusals. All six directed pairs need acceptance cases over actual local protocol modules. Protocol/environment mapping, uint64 decimal sequence, origin/wrapped identity, normalized amount, dust disposition, fee and net recipient amount are frozen. Canonical body digest and unique emitter/sequence conflict identity jointly fence target claims. Final consumed-proof and bridge projection settle atomically; projection loss never reopens redemption. Outbound redemption still possible precludes automatic source refund. Return transfer requires current holder authority.

### Causal compensation and template authority (R5, R7)

B's concrete matrix classifies every domain: exact-version local rollback where still safe; independently authorized reverse economic operation; immutable retained external effect; or unresolved original effect. Already-admitted parallel branches settle before compensation decisions. Reverse dependency order comes from the frozen DAG and confirmed forward receipts, not timestamps. Each reverse has its own durable identity, consent/fee cap, current ownership proof and authoritative result. Local rollback cannot overwrite intervening updates. A per-run audited operator/participant journey discovers pending reversals and explicitly retained effects, preserving forward receipts. No actor acquires a recipient's signing authority through compensation. Terminal outcome names must distinguish fully reversed, partially reversed/retained, and still unresolved effects.

Keyed template authoring defaults to the intended runner principal: forActor acquires the child's credential before both authoring and start; a parent API key grants only credential delegation already authorized by existing policy. Parent-authored child-running is a separate explicit mode with immutable author/runner scope and actual visibility/authorization; it cannot be inferred from the convenience call. Template revision, canonical substitutions, tenant, author, runner and copied graph identities are persisted atomically before create. Exact replay resolves the authored result before mutable template reads. Publication and economic consent remain explicit: a newly copied draft is not silently executable. Discovery by original scoped request must survive browser loss. The reviewed amendment must make the convenience usable without bypassing those publication/consent boundaries.

### Native outcomes and Emit delivery (R8)

Native resource/effect evidence is independent of orchestration terminal state. A confirmed deploy/upgrade with failed authority removal is deployed with pending hardening. Quoted fallback CloseBuffer is separate from the normal success stage list, pins the original authority/refund destination and is allowed only with proven resolved original generation and no deployed-resource destruction. Budget exhaustion uses a separately quoted linked operation with fresh consent and an atomic parent-to-child fence that prevents a delayed original stage racing cleanup. Returned rent is observed balance evidence, never an estimate relabeled refunded. AVM IDs use strict unsigned decimal strings across public API, SDK, persisted intent, metadata and DEX, without a JSON-number intermediate.

Emit's node successor promise is **durable outbox acceptance**, not receiver delivery. The outbox event and action-domain receipt commit atomically under frozen action authority. Immutable payload, tenant registration/destination identity and stable event ID survive every retry. Delivery exposes accepted/delivered/retrying/dead-letter separately, with audited retry/discovery and existing SSRF/signature controls; arbitrary action URLs do not manufacture destinations or credentials. Receiver delivery remains explicitly at-least-once. An HTTP response loss can repeat the same event identity, never create a new logical event, and a permanent receiver refusal cannot appear delivered.

The explicit cancellation/rejection requirements above satisfy R6: cancel-by-key atomically competes with admission, winning admitted runs are observed, and a saved pre-dispatch rejection survives before terminal projection without invoking a handler. All eight review corrections are binding; concrete domain amendments are still independently reviewed before corresponding source implementation.

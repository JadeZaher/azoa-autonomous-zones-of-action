# Ethereum DEX unsigned nonce admission

Status: root independently accepted this design. Reservation/signing extraction and focused fixtures are authored and awaiting separate source review; runtime remains unrun. Existing NFT/native/WTT callers retain their reserve-and-sign wrapper contract.

DEX planning cannot call the current `PrepareCallAsync`: that method reserves and signs together, while the DEX domain deliberately persists its unsigned plan before custody and before browser disclosure. A plan also has no custody context yet. Creating an invented signing context or borrowing the policy signer would defeat this boundary.

Extract a reservation-only primitive that accepts the exact sender, target, value, calldata, immutable fee envelope, durable preparation key and owner-domain identity. It continues to use the existing activation checkpoint, protocol/sender/nonce unique index, highest reservation and typed claim path. It returns the saved immutable call and unsigned EIP-1559 bytes without touching custody. Existing `PrepareCallAsync` becomes reserve then sign with its original context and fingerprint semantics; retained old rows decode unchanged.

DEX-owned calls explicitly record an owner descriptor (domain, operation, stage, generation, actor, wallet, tenant, required scope and original plan/quote commitment). Their stored custody context is absent. The immutable fingerprint includes that descriptor and full call/fee identity. Absence of context never means platform authority. Custody signing is a separate method supplied the actual current `SwapSigningAuthority`, validating exact sender/wallet/actor/chain/scope and the domain's saved identity after the existing live authority fence. It rereads current reservation state before custody and CAS-persists the winning real signed candidate; canceled/terminal state cannot initiate a new signature. Browser upload validates real signature, full exact unsigned call and nonce before persisting its candidate. Neither signing nor upload grants egress.

The DEX stage plan stores the nonce reservation identity and exact unsigned bytes. Domain exposure is durable before returning those bytes or the independently signed executor policy permit. A lost outer plan CAS leaves an undisclosed reservation that cannot be auto-sent: only explicit owner-domain submission admission can authorize replay. Such reservations retain the existing usable same-nonce cancellation path rather than recycling a possibly exposed nonce. Generic recovery cannot resume DEX calls directly; it routes resume through the saved owning operation. Owner-authorized nonce cancellation remains available using fresh actual caller authority and the saved wallet/owner descriptor, without fabricating the original workflow's Running state or reusing a stale grant.

The independent policy permit key is selected only from the explicit DEX key-version catalogue matching the immutable deployed executor signer/version. It is not a wallet transaction key. Its permit signs only the canonical server-owned executor payload after quote/operation binding, never client-provided economics. Preparing a permit does not grant egress, and disclosure is covered by the domain exposure transition.

Observation of exposed unsigned calls must discover a real finalized transaction by exact sender/nonce and compare the full admitted call. A different finalized nonce winner proves the original cannot execute; no pending/latest count, elapsed deadline, or missing hash alone releases the reservation. Persist bounded finalized block search progress and original network identity. Preserve canceled/reverted audit and require explicit new generation after authoritative no-effect. Exact allowance reset/approval lanes remain operation-owned prerequisites and require their own confirmed receipts before executor submission.

Required fixtures: old wrapper byte/identity compatibility; unsigned planning never calls custody; shared concurrent signer nonce uniqueness across DEX and existing callers; lost outer-plan CAS cannot auto-send; cancellation racing delayed custody; changed wallet/context refusal; browser exact-wire admission; policy-key mismatch; exposed hashless discovery, alternative finalized nonce winner and pruned-history ambiguity; owner cancellation of orphan unsigned reservations without impersonating a completed workflow. Runtime execution stays at the final integrated gate.

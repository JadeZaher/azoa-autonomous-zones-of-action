## Required corrections recorded during the initial pass

1. **Make the two deployment products explicit and preserve the runnable dApp promise.** Add a versioned target discriminator to generation/deployment contracts and all clients. An existing Algorand/Solana target must not silently become platform registration merely because the implementation cannot compile arbitrary graphs. The platform target must generate a runnable loader/client artifact with an actual reachable invocation route and versioned runtime registration; demonstrate invocation through that artifact. The native target requires actual native artifact input and confirmed deployment identity. Receipts must discriminate platform activation from chain confirmation and never invent a chain hash for activation. Legacy generated configuration is not an executable artifact and must be regenerated/migrated explicitly. The existing public UI calls this "Generate dApp"/"Generated Code" and provides a chain-targeted Deploy button; changing those meanings requires coherent UI/API/SDK migration, not only a new backend status name.

2. **Pin executable dependencies and separate deployment authority from invocation authority.** The lane C amendment must bind executable graph/version, bound action/Holon references, target/network, compiler/runtime version and artifact digest before admission. A reference changing after admission must not silently alter an old deployment. Define immutable snapshots or content-version references and conflict behavior. Invocation must authenticate its actual actor/tenant, recheck current permissions and required consent, and use that caller's authorized signing context. Bundle ownership/publication does not delegate the publisher's wallet to every invoker. Include private-reference leakage, revoked consent, altered referenced graph and cross-tenant invocation cases. Apply target overrides before artifact validation and admission; an override that requires different compiled output requires a new artifact rather than reinterpretation of the old digest.

3. **Bound lane B with a handler recovery matrix and a shared operation envelope before parallel adapters.** "Classify each effectful handler" is a required deliverable with handler name, durable key, stored operation identity, retry/observe action, terminal proof and remaining recovery seam. Cover existing transfers/allocation/release/refund/swap/bridge/deployment and external effects, not only the new NFT nodes. A missing/Running node must never return successful advancement, and an ambiguous handler with no observation path needs an implemented operator reconciliation contract rather than an infinite parked record. Freeze the minimal pending-operation/result envelope between lanes B and C before deployment/action adapters are edited. Source changes for DEX/Wormhole can remain scheduled in Round 3, but Round 2 must identify their exact parked/recovery dependency instead of counting those handlers as complete. A signed existing operation may be observed/replayed without new consent; fresh stage/generation/signature work remains interactive and explicitly authorized.

4. **Settle the native artifact execution and resource-authority boundary in the amendment.** Enumerate the actual first-class supported artifact kinds/toolchains and pinned local fixtures for AVM, Solana programs and Ethereum bytecode. Do not turn submitted source/config into arbitrary host shell execution or an unrestricted build script. Specify compiler location, isolated execution/input limits, output identity and how a precompiled artifact is validated. Bind program/app IDs, deploy/upgrade authority, fee payer, rent recipient and authorized fee/rent ceilings to the immutable request. Multi-stage deployment must preserve account/nonce/program identity and recover partial uploads/authority changes without a second deployment or misleading refund. A generic "typed inputs" promise is not yet a reviewable signing contract. All these details belong in the separately reviewed lane C amendment before its source work; the main plan must explicitly require them.

5. **Specify governance authority and cutoff semantics at the common direct/action boundary.** Use a conservative documented policy: tenant-authorized immutable electorate/eligibility snapshot, required `closesAt`, fixed server-authoritative voting cutoff, authorized finalization after that cutoff, and no implicit early-close capability. State how membership removal/new members, revoked identity and in-flight ballots affect eligibility and the final tally. Preserve claim-ledger tally reuse. `TenantAuthority.CheckAsync` only establishes that a named tenant is active and has provisioning authority; it does not establish the calling actor's right to govern that tenant. Require authenticated actor-to-tenant ownership or an explicitly verified delegated capability at the common Holon/action mutation boundary. A supplied ActingTenantId, active tenant lookup, readable public proposal or ordinary electorate membership alone must not authorize proposal creation/finalization. Pin proposal/claim vote-cutoff CAS semantics so later claim mutation/release cannot silently change a finalized result. Gate removal remains contingent on separate review and eventual executed acceptance.

## Accepted aspects and scope controls

The plan correctly retains Identomat's two evidenced external blockers without extending them to implementation gaps. Missing Veriff/generic deployments cannot excuse their adapters/protocol fixtures. The generic provider protocol must remain explicitly opt-in to configured trusted issuers and cannot make arbitrary caller-selected endpoints approval authorities; this follows the proposed authenticated, versioned protocol and should be explicit in its amendment/fixtures.

Round 1 solved surfaces are correctly identified for reuse: hosted admission/lease fences, prepared NFT/value wire, provider-owned canonical encodings, durable nonce allocation and claim-ledger tally. Do not reopen these as rewrites without a concrete contradictory finding. The proposed NFT worker restriction is appropriate: observation and exact authorized replay are allowed, fresh signing/acceptance is not. Preserve fair per-record and per-network progress, including the Ethereum worker correction already reviewed.

DEX and Wormhole are concrete scheduled Round 3 implementation work, not external deferrals. Their route/toolchain breadth should be bounded by a concrete capability matrix in that fresh round. The last-round full-goal assessment must still search for production false-success and unconditional refusal paths; completing only the named packages is not equivalent to the user's all-stubs objective.

The plan correctly distinguishes authored fixtures, source review, executed local/persistence/protocol evidence and vendor DEV acceptance. Continue reserving actual execution for the final integrated sweep under the user's policy. Final clean main, commit/push and freshly verified branch ancestry remain outstanding acceptance work. No source-only verdict can mark those complete.

## Correction reread and acceptance

The root revised the plan and this reviewer reread it. Explicit target discrimination, immutable executable dependencies, invocation-time authority/consent, bounded native toolchain/resource authority, the handler recovery matrix and common governance authority/cutoff policy now address the five findings. The final two corrections also landed: B/C must freeze a server-registered immutable pending-operation envelope before adapter edits, and governance finalization atomically preserves the eligible-vote/tally/cutoff evidence against later claim or membership changes.

The main plan is accepted. Lane C may research and author its concrete amendment but cannot begin implementation until that amendment separately passes review. Legacy configuration regeneration, discriminator-specific deployment receipts, target override artifact regeneration, actual runnable client/runtime behavior and concrete native artifact formats remain mandatory details of that amendment, not waived requirements. Assigned lanes may proceed under the corrected plan and announced file ownership. Runtime acceptance remains entirely pending.

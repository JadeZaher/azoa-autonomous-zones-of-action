# Round 3 DEX execution contract

This amendment completes the existing swap feature through provider-owned transaction modules. It replaces the memory-only quote cache, ignored execution key and unsigned-transaction-as-execution response. A swap completes only with authoritative economic settlement. Root independently accepted the design with the fee-denomination and independent-policy-key clarifications recorded below. Source and runtime review remain separate gates; no builds, tests, protocol execution, signing or public-network economic operations have been performed.

## Ownership and seams

A owns `Services/Dex`, new `Models/Dex`, `IDexTransactionModule`, `IDexQuoteStore`, `ISwapOperationStore`, new quote/operation POCOs and typed stores, provider `*.Dex.cs` partials and DEX-only helpers, swap API contracts/controller/manager, DEX SDK module and swap dashboard. Root retains Program, shared preparation contracts, common identity/AVM integer helpers and generated schemas. B retains action registry/frozen authority fences: A supplies a `swap` domain resolver and minimal registry registration request. C owns WTT; existing native provider partials remain Root-owned.

`IDexTransactionModule` is implemented by each immutable chain/network provider. It owns capability discovery, quote/evidence validation, stage planning, prepare, exact-wire validation, submit, observe and cleanup planning. Its provider-neutral observations distinguish `Pending`, `Confirmed`, `FailedOnChain`, `ExpiredAbsent` and `NeedsOperator`, with immutable transaction and economic evidence. Generic services do not switch on chains or interpret protocol wire. HTTP pricing adapters can remain provider collaborators; they cannot sign or declare settlement.

The new domain contracts use `DexQuote`, `SwapIntent`, `SwapOperationView`, `PreparedSwapStage` and `SwapStageObservation`. Existing `ISwapManager` routes delegate to the durable service; there is one execution authority. SDK browser execution signs only the server's exact admitted stage, uploads the signed envelope for validation/persistence, then uses the same submit/observe lifecycle. Custody actions use the existing scoped signing grants. Returning a built unsigned payload remains a named preparation response, never a successful swap.

## Identity, consent and persistence

All base-unit amounts and AVM asset/application IDs are strict canonical unsigned decimal strings. Provider checks enforce uint64 for AVM/SPL and uint256 for EVM; no JSON-number intermediate or uint32 narrowing. Chain, network profile and genesis/chain ID are distinct immutable fields. EVM address canonicalization and Solana case preservation use the shared provider identity helpers.

`dex_quote` stores a versioned normalized request and canonical digest, authenticated actor/tenant, asset-owner wallet ID/address, recipient, payer, chain/network/protocol identity, exact input and output assets, exact-input mode, gross debit, platform fee, net swap input, expected output and minimum output, slippage, expiry, protocol/pool/router/program identities and code/version evidence, observed block/round/slot, route/account evidence, fee-policy revision, treasury, maximum network cost, maximum prerequisite rent/minimum balance and cleanup budget. Raw provider responses are private evidence; public views contain no signing context, secret or private wire. Quote evidence is immutable after creation. Unknown/missing fee policy is not silently zero.

`swap_operation` is uniquely claimed by `(actor, tenant, original idempotency key)` with canonical full intent hash. It binds exactly one quote and an immutable authorization snapshot. The same key with changed quote, recipient, amount, wallet, network, budget or consent conflicts. Original-key replay/discovery resolves this record before consulting quote expiry or mutable current configuration. A quote can be consumed by only one logical operation. Quote expiry prevents new admission, not recovery of an already admitted operation.

`swap_stage` has unique `(operation, stage, generation)` and preparation identity `swap:<operation>:<stage>:<generation>:<intentHash>`. It stores exact immutable prepared bytes/hash, provider recovery metadata, signer and payer roles, prerequisites, first-send authority, observations, final receipt and actual network/prerequisite costs. Stage generation cannot change on timeout, changed quote or missing RPC result. Only authoritative final failure/expired-and-finalized absence permits replacement under the original amount/fee limits and fresh current authority for any new signature. A replacement must retain the original consented minimum output; a worse quote needs a separate explicit new consent/operation after the original is proven unable to settle.

Preparation is not egress permission. The store atomically moves a prepared stage to `SubmissionAuthorized` while checking operation version, cancellation state, quote admission, current direct signer authority and, for actions, B's exact frozen action authority fence. Workers may observe/rebroadcast only authorized exact saved bytes. A losing preparer has no usable egress authority. Browser signatures must match the stored unsigned message and expected signer set byte-for-byte; arbitrary transaction upload is forbidden. Recovery never manufactures a participant signature. Cancellation before this CAS wins without economic effect; after it, cancellation waits for authoritative original resolution before cleanup or a new generation.

Suggested public states are `AwaitingSignature`, `Preparing`, `Pending`, `AwaitingCleanup`, `Completed`, `Failed`, `Cancelled` and `NeedsOperator`; the stage/effect list separately shows retained approvals, opt-ins, account rent, network fees and confirmed swap output. A failed swap with an existing opt-in is not a full rollback. Completion and final economic receipt commit atomically with domain projection; a lost response cannot reopen settlement. Queries are owner/tenant-authorized; operator recovery requires the existing recent-node-operator policy, reason and expected version and can only retry observation or already authorized wire. It cannot override amounts, evidence, owner or terminal state.

Workers use durable next-attempt timestamps and bounded fair pagination, isolate expected per-operation dependency failures, preserve cancellation and surface unexpected infrastructure failures at the worker boundary. No old unresolved operation may monopolize the first page.

## Fee contract

Reuse the existing node fee schedule's `Swap` entry rather than introducing an unrelated hidden fee policy. Source tracing found that `NodeFeeScheduleManager.QuoteAsync` adds the flat integer directly to a percentage of the caller's integer gross amount, the POCO serializes only `SwapFlatBaseUnits`/`SwapBps`, and node-transparency labels it only "Flat (base units)". There is no existing asset or decimal denomination to convert reliably. Add a versioned `SwapFlatDenomination` value `input-base-units-v1`, exposed through the existing schedule update/response/SDK/operator display. A new or explicitly updated schedule declares this denomination; an ambiguous legacy nonzero flat schedule refuses DEX quoting until the authorized schedule update records its intended denomination. A legacy zero flat value can be adopted under a conditional audited migration because zero has the same value in every denomination; do not reinterpret a nonzero legacy value automatically. This is a real migration/update path, not an indefinite runtime refusal.

For that declared policy, `fee = flat + floor(gross * bps / 10000)`, `netSwapInput = gross - fee`, requiring `0 <= fee < gross`. Pin denomination version, schedule version, input asset/decimals, treasury address and original owner as fee payer in the quote. Show gross debit, fee, net input and minimum output before consent. The route quote uses net input. Protocol LP fees are separately disclosed and already reflected in quoted output. Network fees and rent are separate explicit caps. Positive fee settlement occurs atomically with the successful swap; approval/account creation alone charges no platform fee. Zero is an explicit schedule result. No background service charges a second fee for replay or cleanup.

Tinyman adds the exact input-asset treasury transfer to the atomic swap group. Solana adds one exact SPL `TransferChecked` (or native transfer for native input) to the same transaction as the Jupiter route, with the treasury destination account verified. Jupiter's own `platformFeeBps` stays zero so there is no second aggregator fee or 8-bit percentage mismatch. Ethereum uses the small reviewed settlement executor described below to combine fee and router effect atomically. All three validate the entire final wire including this transfer. Fee settlement projection uses the same operation identity and confirmed receipt, not an off-chain balance.

## Algorand: Tinyman V2

Baseline is fixed-input, one verified Tinyman V2 pool, ASA/ASA or ASA/ALGO, self-recipient. This is a protocol-shaped constraint: the official validator transfers output to the app-call sender. API capability discovery must say self-recipient rather than silently ignore a requested recipient. No liquidity creation, arbitrary app call, flash loan/swap or fixed-output operation is exposed through swap.

Pin validator application ID, genesis and exact approval/clear program hashes. Verify the pool address from the pinned pool-template logic-signature program and ordered asset IDs; validate its validator local state, asset identities, reserves and fee configuration at a recorded round. Never trust a pool API address without this proof. Quote from current `asset_1_reserves`, `asset_2_reserves`, `total_fee_share` and `protocol_fee_ratio`; do not hardcode 30 bps. The official integer calculation is `totalFee=floor(input*feeShare/10000)`, `swapAmount=input-totalFee`, `output=outputReserve-(floor(inputReserve*outputReserve/(inputReserve+swapAmount))+1)`. Preserve that deliberate rounding, including exact division, with BigInteger intermediates and uint64 result bounds. Reject zero fee/output or insufficient liquidity when the validator would reject.

The fixed-input group contains the exact payment/asset transfer from owner to pool, then validator `NoOp` with arguments `"swap"`, `"fixed-input"`, uint64-big-endian minimum output, foreign assets in the official pool order and pool account. Optional platform-fee transfer is placed where it does not change the validator's preceding-input invariant. The normal app call pays for its inner output; recompute the complete pooled network-fee cap from current minimum fees and exact transaction count. Every member binds the same genesis, valid-round interval and group hash. Reject rekey, close, asset close, clawback/revocation, unrelated notes/accounts/applications and appended MessagePack objects. Reuse `AlgorandSignedEnvelope.DecodeCanonical`.

If output ASA opt-in is missing, a distinct signed prerequisite self-transfer with exact asset/zero amount is recorded before swap. Quote its minimum-balance reservation and fee. No user validator-app opt-in is invented: the pool has the validator local state. A cancelled/failed swap exposes the retained asset opt-in. An explicit owner-authorized cleanup can close only the exact newly created, still-zero holding after proving all original swap generations terminal; it never closes a preexisting holding or destroys received value.

Settlement requires confirmed group membership and exact outer/inner transfers, correct validator/pool/assets/sender/recipient, actual input and actual output at least the bound minimum, fee transfer when nonzero and recorded canonical chain evidence. A group hash or pending tx ID is not success. Expired absence requires the existing same-genesis finalized round/indexer checks before generation replacement.

## Solana: current Jupiter Build API with bounded Whirlpool grammar

HTTP contract is official `GET https://api.jup.ag/swap/v2/build`, `x-api-key`, fixed decimal `amount`, `inputMint`, `outputMint`, `taker`, fixed integer `slippageBps`, `dexes=Whirlpool`, explicit `payer=taker`, `platformFeeBps=0`, `wrapAndUnwrapSol=false`, `transactionVersion=0`. Do not call the existing nonexistent `/swap/v2/quote` or `/swap/v2/swap`; Build instructions are self-compiled/submitted through the bound RPC, not `/execute`. No RTSE, tip, RFQ, token-ledger, exact-output, split or multihop route is accepted in this baseline. RoutePlan must describe one 100%/10000-bps Whirlpool hop from the exact input to output and the same pool as the account evidence. A different route is a precise unsupported capability result; absent liquidity/dependency outage retains existing `Unavailable: true` quote semantics.

The authoritative wire schema is **jup-ag/jupiter-amm-implementation `cc068c9d1df0060c62f9a8a4fc37ea13ea7b9b39`**, `idls/jupiter_aggregator_v6.json`, `idls/jupiter_dex_interfaces.json` and `jupiter-core/src/swap_transaction/build_swap_instruction.rs`. Program is `JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4`. Accepted Anchor discriminators are `route=[229,23,203,151,122,227,173,42]` and `shared_accounts_route=[193,32,155,51,65,214,156,129]`. The latter begins with authority ID u8. Both then encode Borsh vec<RoutePlanStep>, input u64, quoted output u64, slippage u16 and platform fee u8. Vector length is exactly one; step contains swap enum, percent u8, input/output index u8. Input/output indices are the single-hop topology, and the decoded minimum implied by quoted output/slippage must equal the persisted floor. Require complete byte consumption, canonical booleans/options and bounded vectors.

Accepted Swap variants are **17 `Whirlpool { a_to_b: bool }`** and **47 `WhirlpoolSwapV2 { a_to_b: bool, remaining_accounts_info: Option<RemainingAccountsInfo> }`**. V2 supports the standard SPL-token case with no transfer hooks; remaining-account slices may only be the explicitly validated supplemental tick-array form from the pinned IDL. Unknown enum tags, mixed token programs or token2022/hook/transfer-fee tokens are rejected. The Rust `jupiter-amm-interface::Swap` ordinal is NOT the wire ordinal; the official aggregator conversion maps it. Old instruction-parser header arrays omit Anchor event accounts and must not define account positions. The separately discovered Surfpool scenario IDL has conflicting discriminators and is not trusted wire evidence.

`route` has nine fixed accounts: token program, user transfer authority, user source token account, user destination token account, optional destination account, destination mint, optional platform fee account, event authority, program. `shared_accounts_route` has thirteen: token program, program authority, user transfer authority, user source, program source, program destination, user destination, source mint, destination mint, optional platform fee account, optional token2022 program, event authority, program. Optional-none sentinels must equal the canonical program sentinel, not arbitrary accounts. Event authority derives from `__event_authority`; shared authority derives from `["authority", authorityId]`, with accepted IDs 0..7 from the pinned official CPI helper. Shared source/destination accounts must have the bound mints and this exact PDA owner; user accounts belong to the bound owner/recipient. No unbound authority or delegate is accepted.

The AMM remaining accounts are validated against the pinned Whirlpool instruction schema and program `whirLbMiicVdio4qvUfM5KAg6Ct8VwpYzGff3uctyCc`, not merely allowlisted. V1 accounts bind SPL token program, transfer authority, whirlpool, owner A/vault A, owner B/vault B, three tick arrays and oracle. V2 additionally binds both token programs, memo program and both mints, with writable oracle and only recognized supplemental tick arrays. The AMM program account prefix and exact account count/order come from the official aggregator builder/interface, with golden fixtures for both routes and variants. Decode pool state to verify mint/vault identities, direction, tick spacing and tick-array pool affiliation; derive oracle/tick PDAs and verify program ownership. Verify the entire compiled privilege union, including duplicate account aliases: only fee payer/owner, exact token accounts, pool/vault/tick/oracle state and explicitly derived prerequisite accounts may be writable; only expected wallet signers may sign.

Resolve every address-lookup table from the bound RPC at a recorded context, verify table owner/state/index bounds and selected addresses, and compare to Build's lookup map. Do not trust the HTTP-supplied map. Persist the exact resolved message and table evidence. Reject unresolved/deactivated/changed table entries, cross-genesis context, unexpected writable program accounts and extra instructions. Canonical decoding rejects appended wire.

Whitelist setup by exact semantics: associated-token-account create-idempotent for the bound recipient/mint/payer only; bounded System account creation/funding for operation-owned wrapped SOL; exact SPL initialize/sync/close for those accounts only. Existing arbitrary WSOL accounts must never be closed. Compute instructions are limited to one explicit unit limit and price within quoted caps; no heap/data-size changes, duplicate override or tip instructions. API-provided unit price does not authorize unlimited compute. Unknown `otherInstructions` are rejected. For native SOL, build and persist a dedicated operation-owned WSOL lifecycle with explicit funding and rent; wrapping, route and cleanup are atomic where the transaction limit permits, otherwise durable prerequisite/cleanup stages with the same authority and cost rules. Native output unwraps only an operation-owned account to the bound recipient. Standard SPL output ATA may remain as disclosed rent; closing it needs current owner consent and zero balance.

Finalized settlement verifies signature/message identity and genesis, `meta.err == null`, exact decoded outer and inner instructions, authenticated pool route and input debit/output credit in raw token units, recipient ownership, fee transfer and rent/network cost. Missing/truncated logs cannot substitute for transaction/account evidence. Failed finalized transactions retain consumed network fees. Unseen transactions remain pending until the saved blockhash's final expiration/absence proof; a new Build response cannot overwrite saved signed wire.

## Ethereum: Uniswap V3 exactInputSingle and atomic fee executor

Use the classic pinned `ISwapRouter.exactInputSingle((address tokenIn,address tokenOut,uint24 fee,address recipient,uint256 deadline,uint256 amountIn,uint256 amountOutMinimum,uint160 sqrtPriceLimitX96))`, not Router02/UniversalRouter with a guessed ABI. Pin v3-core `aab5aa019b5acb312acc01aff7f03a1b09755197` and v3-periphery `7c8367c896ec8514198a8c03e5b0668c8b207a79`. Ethereum mainnet official classic router is `0xE592427A0AEce92De3Edee1F18E0157C05861564`, factory `0x1F98431c8aD98523631AE4a59f267346ea31F984`, Quoter `0xb27308f9F90D607463bb33eA1BeBb41C27CE5AB6`. These addresses are not defaults for Sepolia or local networks; the official deployment table leaves classic Router/Quoter empty on Sepolia. Local fixture deploys the pinned actual factory/router/quoter/WETH and initialized liquid pool. A configured test profile must supply its own matching verified deployment.

Quote one factory-proven pool for the selected standard token pair and fee tier using pinned Quoter eth_call at a recorded block; bind pool address, token0/token1, fee, factory/router/quoter/WETH code identity and chain ID. `sqrtPriceLimitX96=0` means normal full exact-input execution, with the explicit minimum output enforcing slippage. Nonstandard rebasing, transfer-tax, callback tokens and arbitrary proxy implementations are excluded by a reviewed standard-token deployment/code policy and verified runtime behavior. No user calldata or arbitrary recipient router command is admitted.

Implement a small non-upgradeable `AzoaDexExecutor` rather than pretend an ERC20 fee transfer can be made atomic by two separate transactions. Immutable constructor binds classic router, factory, WETH and platform policy signer. The policy signer is a separately configured authority with an explicit retained key version, independent from user/platform wallet transaction keys; no wallet-secret fallback is permitted. Quote and preparation pin its version/public address, executor deployment and verified runtime bytecode/configuration. Missing or unavailable matching policy key makes new preparation unavailable; existing signatures and authorized wire remain recoverable. Rotation uses a separately verified executor/configuration revision while retaining the old key only for its explicitly permitted outstanding preparations; it cannot silently change an old quote's authority. Local fixture generates a dedicated test policy key and verifies the deployed bytecode/constructor configuration.

The exact-input call accepts the full immutable operation/quote hash, owner (`msg.sender`), recipient, input/output identities, gross/fee/net/minimum output, pool fee, deadline, treasury and platform policy permit. EIP-712 domain binds chain ID and executor; permit binds the entire quote including fee revision and operation identity. Consume operation identity once inside the successful transaction. Owner allowance/native value is explicit authority; a policy permit alone cannot spend another owner. No arbitrary call/delegatecall, operator withdrawal or reusable general permit is exposed.

Executor pulls exact gross standard ERC20 (or wraps exact native gross), checks balance delta, transfers the exact input-denominated platform fee, grants router only exact net allowance, performs exactInputSingle, clears any remaining router allowance, verifies actual output and forwards to bound recipient (unwrap WETH only for explicit native output). All revert together on failure. Reentrancy guards cover token/router/recipient/treasury callbacks. Token balances are reconciled to pre-call values so previous dust is not assigned to another caller. EIP-712 policy permit is produced only from the persisted server-selected quote, never arbitrary client fee input. Native input/output and WETH are explicit different public asset choices, not silent conversions.

User-to-executor allowance is a durable prerequisite: if a nonzero existing allowance must change, confirm reset-to-zero first, then approve **exact gross**. Never authorize unlimited allowance. After a failed/cancelled swap, owner-authorized cleanup resets only the operation's still-relevant allowance after all original generations resolve. Concurrent swaps sharing `(owner, token, executor)` acquire a durable allowance lane so one cannot erase or reuse another's prerequisite. Do not overwrite an unrelated preexisting allowance without explicit quote disclosure/consent. All approvals, swap and cleanup use the existing shared durable Ethereum nonce allocator, saved bytes, activation checkpoint and cancellation/replacement controls; no direct provider broadcast bypass is added.

Completion requires canonical finalized receipt with exact sender/nonce/to/value/calldata, executor's operation event, factory-proven pool Swap event and exact token recipient/treasury effects; amount-out and gross debit must agree with saved intent and event/transfer evidence. A mined revert is `FailedOnChain`, not expired absence. Pending cancel remains non-egress pending. Saved operation receipt survives configuration/fee-policy change and response loss.

## Direct, action, SDK and dashboard behavior

### Browser disclosure is potential egress

Root adversarial review accepted this correction during public integration:
returning executable unsigned wire or a platform policy permit requires explicit
participant consent and a durable external-signing-exposed transition first.

The implementation separates `ExternalExposedAt` from server `AuthorizedAt`.
Exposure persists the original consent identity, exact plan and provider-derived
transaction identities before returning wire, and moves the operation to Pending.
No unsent cancellation can release its budget afterward. Returning a correctly
signed original envelope may fill the candidate, but never grants server egress;
that still needs the live submission fence. Recovery observes exposed plans with
or without a returned signature and only rebroadcasts server-authorized bytes.
Confirmed discovery stores actual recovered signatures from chain evidence. A
finalized no-effect observation without a signature is represented explicitly as
an exposed plan and provider proof in history, never a fabricated signed
candidate. Only that authoritative outcome permits a new preparation generation
under the original caps. Whole source/runtime review remains a separate gate.
That transition binds the exact unsigned hash, owner, budgets and original
preparation identity. Exposure is potentially submitted even if the server never
receives a signature or transaction hash. Cancellation can only withdraw future
server submission; it cannot declare chain absence or release reserved budgets.
Replacement requires authoritative finalized no-effect evidence, including the
existing nonce-winner rules on Ethereum. Provider-owned exposed-plan recovery
must find the original transaction semantics or prove the original window cannot
execute without fabricating a signature. Custody-only undisclosed plans retain
the ordinary provably-unsent cancellation path. Public browser routes remain
unwired until this required recovery path is implemented and reviewed.

Quote requires authenticated actor, owned wallet and explicit network. Execute requires original request key plus quote hash and maximum fees/prerequisite-cost consent; it returns a durable operation, usually HTTP 202. GET-by-operation and GET-by-original-key recover across browser/server loss. Refresh and explicit cancel/cleanup are versioned owner-authorized operations. Public status never asks the browser to infer completion from presence of a transaction hash.

`SwapNodeHandler` freezes quote policy/limits and delegates to the `swap` resolver under B's current action fence. It parks on pending/participant/cleanup states. A successor receives actual confirmed output/receipt only. Compensation is an independently quoted reverse swap by the current output owner; it is not rollback, cannot promise the original price and cannot borrow the recipient's signature. Forward receipt and retained protocol/network fees remain visible.

SDK and dashboard enumerate provider capabilities instead of fixed chain lists. Persist exact quote hash, owner/account+network scope, request key and fee consent before send; response-loss retry reuses the same body. Account/run selection generation fences all asynchronous projection. Show expected versus minimum versus actual output, pending prerequisites, retained allowance/opt-in/rent, actual costs, cancellation/cleanup and operator needs. Quote Unavailable is an ordinary empty-state with reason; unsafe/inconsistent provider evidence is a refusal, not unavailable liquidity. Remove the current synthetic-success/unsigned-only execution affordance when the real lifecycle replaces it.

Jupiter parser goldens from the pinned official IDL/builder, both route headers and Whirlpool variants; direct and shared accounts, ALT substitution, writable aliases, wrong pool/vault/mint/tick/oracle, unrecognized variant, token2022/hooks, extra signer/fee/tip/transfer/close, uint64 and trailing-wire rejection. Actual local validator fixture uses the official repository's pinned Jupiter V6 binary and a pinned Whirlpool binary with real funded pool/account state; hash artifacts and verify local genesis before funding. The production .NET module and durable store execute actual swap/settlement, not a program that only returns success. A recorded/current Build response conformance fixture covers HTTP-to-wire compatibility separately; HTTP fixtures do not claim live Jupiter availability.
4. Ethereum actual local pinned Uniswap factory/router/quoter/pool plus executor: exact-input native/ERC20, positive/zero fee, approval reset/exact allowance, concurrent same-owner lane, replay/crash/revert/cancel, min-output failure without platform fee, treasury/recipient reentrancy, forged zero-fee/revision/treasury permit, cross-chain/executor replay and final receipt semantics. Reuse existing provider/nonce store infrastructure rather than mock it away.
5. SDK/dashboard/action tests cover lost responses, stale quote replacement only after authoritative no-send outcome, account/network switching, no successor before economic settlement, retained effects and explicit reverse-swap consent. Registry/provider/API/SDK/UI capability matrix must match the bounded grammar above.

These are implementation requirements, not deferred items. Runtime execution remains the final integrated sweep. Public activation needs matching configured deployments and successful protocol evidence; missing environment credentials/liquidity are reported as environment readiness without declaring source or settlement complete.

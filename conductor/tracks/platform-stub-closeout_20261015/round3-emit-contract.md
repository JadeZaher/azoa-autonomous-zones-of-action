# Emit durable acceptance and tenant webhook delivery

The workflow promise is durable outbox acceptance. Emit returns its exact configured payload only after an immutable action-domain receipt and, for a tenant delivery, its outbox event commit atomically. Success does not mean receiver settlement or delivery. A non-tenant Emit has an immutable local receipt and no webhook destination. A tenant Emit requires an active authorized registration; missing registration cannot be silently swallowed while claiming its webhook was accepted.

## Immutable event and atomic acceptance

Use a deterministic event/receipt identity derived from domain, run, node, actor and tenant, with frozen canonical intent hash. Pin the configured payload/event name, action identity and registration ID plus endpoint identity/version in the receipt and event; never use a fresh random event ID during recovery. Existing equal receipt replays before mutable checks; conflicting payload/destination/identity is refused. The actual action admission envelope, current execution fence and current active tenant registration are checked in the same atomic outbox+receipt mutation. Infrastructure exceptions bubble to the established worker/HTTP boundary rather than become a successful Emit. Ordinary store operations use the existing public generated ActionWebhookEvent POCO and typed queries; remove the private duplicate/raw CRUD as this store is touched.

The domain resolver loads and verifies this saved receipt/event. Its terminal success criterion is accepted outbox+payload, not live HTTP. Compensation records accepted external delivery as retained; it cannot recall a receiver effect. Registration changes after acceptance never reroute an old event to a different URL. Disable or destination mismatch pauses/dead-letters delivery visibly. Secret rotation may sign the same original event for its same destination with the current active registration secret, as disclosed by the shared webhook contract.

## Delivery and usable recovery

Workers atomically lease due events with a holder/version and bounded expiry. Every completion/retry/dead-letter mutation compares that claim. At most one current worker owns delivery, but lost HTTP responses may redeliver the same event ID; receiver delivery is explicitly at-least-once. Retain the stable canonical body and occurredAt, changing only delivery timestamp/signature. A valid 2xx is receiver acceptance, never proof of business settlement. Bounded retry errors and final dead letters are discoverable. Cancellation is rethrown; unexpected infrastructure failures remain visible once at the worker boundary.

Authenticated tenant-management endpoints and SDK/UI expose registration status/configuration, secret rotation without GET disclosure, event discovery/detail and audited dead-letter retry with exact expected version/reason. Retry preserves event payload/destination/id; it cannot reset a delivered event or create another logical event. The reserved recent-auth operator may inspect/retry within existing policy, with an immutable audit receipt; tenant access requires actual tenant-management authority, not a caller-chosen tenant ID. Do not expose secrets or sensitive payloads in general lists.

Source inspection found registration currently has no usable controller and persists its Secret as supplied, with an explicit plaintext-at-rest TODO. This package therefore also implements authorized registration/write/rotation and encrypted-at-rest secret storage using the established platform key-protection facility. Read DTOs never expose stored secret; if a generated new secret is returned at creation/rotation, it is a one-time no-store response to the authorized manager. Existing shared consent delivery must use the same decryption seam and remains compatible. A missing configured encryption key is a visible configuration error, never plaintext fallback.

Use the shared webhook SSRF guard and safe HTTP transport: HTTPS only, no redirects, public-address validation and connection binding to the validated resolution so DNS rebinding cannot cross into private/link-local/metadata destinations. Action payloads cannot choose arbitrary URLs or credentials. Destination/secret changes are authorized and audited; new destination identity applies only to new events unless an explicit reviewed redelivery contract is implemented.

## Acceptance and ownership

Root owns this contract, ActionWebhookEmitter/store/worker, generated event model, registration endpoint/store protection and clients. B reviews the contract, atomic action admission and resolver; B registers the domain after root handoff. C or A independently reviews the transport/registration/client portion. Existing consent emitter remains a separate producer; shared registration/secret/transport changes require its regression coverage.

Author real-store concurrent acceptance, crash after outbox receipt before action projection, payload/key conflict, registration-change race, two-worker claim/stale completion, dead-letter retry identity and audit tests. HTTP fixtures cover response loss then identical body/event replay, non-2xx, destination disable/change, secret rotation, DNS/private address/redirect rejection and cancellation. Auth fixtures prove tenant/child/operator boundaries and secret nondisclosure; SDK/UI cover discovery, exact version retries and account switches. No test/build runs until the final integrated sweep.

## Binding corrections from independent review

Recovery with no accepted receipt retries the same deterministic atomic acceptance under the current frozen execution and tenant authority, rather than blindly calling the old emitter. Unique event/receipt keys serialize the original dispatcher and recovery. Deterministic invalid frozen input produces an immutable rejected receipt with no outbox event. Missing/temporarily disabled registration or current authority is retryable and remains unaccepted; it cannot permanently erase a potentially valid receipt or manufacture delivery.

Registration carries a stable registration identity, independent DestinationRevision and SecretRevision, and an overall CAS version. Secret-only rotation retains destination identity; new attempts capture the new secret revision/key identifier without changing event body. URL replacement increments destination revision; deletion/recreation creates another registration identity, even under the same tenant key. Old events remain tied to their original destination and are not rerouted. Disable/re-enable of the same identity/destination may allow an audited retry, while any destination replacement refuses it.

A delivery attempt atomically leases the event and captures authorization for the active registration identity/destination and exact secret revision; registration updates join the same serialization/version protocol. Protected attempt metadata retains access to that revision for the attempt lease. Disable/rotation cannot recall an already authorized HTTP request, and the UI/audit explicitly reports that in-flight possibility. Every subsequent attempt must obtain current authorization. Stale holders cannot complete/reschedule/dead-letter a later claim. Rotated secret retention is limited to live attempts and encrypted storage; no normal response exposes it.

Transport rejects URL userinfo and all nonpublic targets, including IPv6 multicast/reserved/loopback/link-local/IPv4-mapped private addresses. It disables ambient proxies, default credentials, cookies and redirects, binds the connection to validated resolution, retains normal TLS hostname verification and bounds outbound body/header sizes, response headers and timeout. A 2xx response is handled with headers-only completion and disposal; unlimited response bodies are never buffered. Encryption authenticates tenant ID, registration ID and secret purpose/revision as associated data or a verified authenticated envelope. Ciphertext moved between identities fails authentication. Shared consent delivery uses the same binding and transport.

Required fixtures additionally cover admitted-before-acceptance crash/concurrent recovery, secret-only rotation with queued events, replacement identity rejection, disable versus attempt authorization, stale lease completion, credential URLs/multicast/private/proxy rejection, unbounded 2xx body avoidance, cross-tenant ciphertext swapping and absence of secret values from ordinary reads/logs/audits.

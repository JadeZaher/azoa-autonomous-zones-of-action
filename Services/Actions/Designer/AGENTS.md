# Workflow designer

The assistant interviews a tenant developer and returns suggestions. The model service has no manager, store, tool or execution dependency. The authenticated DappDevelop controller calls `TenantAuthority.CheckAsync` before disclosing the owned tenant context and again before every model call: an active owner must hold a live, unexpired `tenant:provision` credential. Drafting adds no KYB or value-execution prerequisite. The UI explicitly selects that server-derived context; the POST tenant id must equal the authenticated owner. Child/acting-tenant credentials are rejected explicitly and the normal child-credential deny boundary remains active. The existing authoring API continues to own persisted drafts and lifecycle authorization.

OpenRouter transport is pinned to the HTTPS completion endpoint, does not forward browser headers, disables redirects, requests providers that deny data collection, disallows fallback and never logs request or response bodies. The system prompt is reconstructed server-side each call; submitted conversation cannot introduce a system/tool role. All replies are untrusted: bounded transport and JSON parsing, closed enum conversion, node allowlist, strict config validation, DAG structural validation and binding executability validation precede import. Identifier fields and GUID values require an exact user-confirmed resource allowlist (GUIDs normalize through `Guid.TryParse`, including N/D forms); this proves user confirmation, not resource ownership or provider validity. Those remain normal runtime authorization checks. A successful shape check is not economic, legal or tax approval. Human review must verify each amount, recipient, handle, quote, gate and recovery path. Generated drafts are always private.

`WorkflowDesigner__Enabled`, `WorkflowDesigner__ApiKey` and `WorkflowDesigner__Model` are process-local/server configuration. Secrets may be injected from the owner's ignored Pi configuration; never copy them into appsettings, frontend variables, source, shell arguments or traces. `WorkflowDesigner__RequestsPerHour` defaults to 12 and is clamped to 1–60. The named canonical tenant-owner partition composes with the global limiter: all of that owner's API keys and JWT sessions share one budget, regardless of key rotation or whether their textual Guid uses N/D form. This is a per-instance request budget with 4,000 output-token cap and bounded intake/history, not a shared fleet monetary budget. Model providers may charge for input/reasoning too; set provider-account spending limits before enabling deployed traffic.

The interview is memory-only in the browser and stateless on the API. It is discarded when the authenticated subject changes. The provider receives the intake/history only after explicit user disclosure acceptance. UI copy warns against personal records and all signing credentials. Draft readiness requires separate user confirmations of jurisdictions and economic terms, non-empty bounded intake, no obvious uncertainty phrase, and no remaining model questions. These are conservative controls, not semantic proof of completeness. Legal/tax references were checked 2026-10-18: IRS digital assets, FinCEN 2019 CVC business-model guidance, and SEC transactions involving crypto assets. They are explicitly US examples; unknown/non-US jurisdictions require follow-up and local professional review, without invented rates or compliance claims.

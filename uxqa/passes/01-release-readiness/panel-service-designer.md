# Service designer lens

The four inspection journeys completed through the visible interface. The strongest service concern is whether people can judge what remains usable when a dependency is unavailable, followed by whether constrained users can reliably reach the next service touchpoint. These are hypotheses from the initial local images, not findings about refreshed images or the final release.

This independent lens read `scenario.md`, `personas.json`, the four lane reports, `ux-report.json`, and every run's `ux.json`. It did not read application source, sessions, trace archives or provider responses, and did not operate the browser. Paths below are relative to this pass directory. Findings do not assert a code cause. Triage must independently confirm any proposed fix against code and recorded UI evidence.

## Service map and observed handoffs

| Job and touchpoints | Observed result | Handoff still unproved |
| --- | --- | --- |
| Newcomer: public offer → member login → operator login | Corrected mobile run reached both sign-in choices in 30 seconds and two clicks, without a failed attempt. Signed-out audit redirected to operator login. | Understanding the economic offer, choosing the correct authority and recovering credentials were not tested with people. |
| Member: overview → wallets → own identity state → settings | Keyboard and zoom/slow lanes completed; empty wallets and not-started verification states were visible. | No wallet connection, identity-provider handoff, account save or value operation was attempted. |
| Operator: readiness → policy audit → tenants → providers | Authenticated inspection completed in 82 seconds, three clicks, with no workaround. Readiness identified configuration work; audit explained its empty state. | No denied permission, expiry during work, provider configuration, ownership transfer or successful remediation was exercised. |
| Owner: unavailable node-admin authority → live root-key drill | Outside this UI panel's evidence. | The capability probe is excluded from UI success. No browser journey establishes that the release owner can complete the root-key drill. |

The member and operator journeys retained useful role distinctions: member login linked to operator sign-in; operator login described deployer responsibility; operator session copy distinguished browser logout from global revocation. These are observed supports for the handoff, not evidence that a person can perform its recovery steps.

The compact-menu and contrast issues may be shared findings with the accessibility lens. Synthesis should merge those observations rather than count each lens as another occurrence or additional participant. Navigation density, provider freshness and recovery wording are research questions; successful agent completion does not establish that they caused real-user harm.

## Evidence quality and automation failures

- The first mobile run's `ABANDONED` result arose before any click because a locator matched two LOGIN elements. Its two attempts are automation strictness failures. The separate corrected run succeeded with the same visible text, filtered for visibility. Preserve both artifacts; do not report human abandonment or erase the original outcome.
- The settings gold run reports `PARTIAL` after four seconds, while its own attempt is marked successful and navigation recorded two distinct pages. The coordinator reports a predicate/navigation timing issue. This lens did not inspect its driver, so the precise mechanism remains a harness interpretation; the four-second outcome alone cannot support a product failure finding. The independent keyboard and zoom lanes did reach Settings.
- The operator report discloses an initial non-TTY harness run with zero page views whose same-task artifact was overwritten by a TTY restart. Its successful inspection is useful, but the missing original artifact limits auditability of that setup failure.
- Anonymous session 401 responses are compatible with a signed-out boundary. Console access-denied messages and zero matched API calls do not establish backend availability or complete request coverage. The study's observer counts configured `/api/` traffic only.
- The generated report includes the harness-abandoned mobile run in raw totals. Its 11/57 visited pages (19.3%) describes coverage, below the configured 20% target. Raw gold success is 2/3 and does not establish comprehension of recovery instructions. Neither raw aggregate is a service success rate for humans.

## Human validation plan

Run **five human sessions per affected segment**. These are qualitative sessions, not a statistically representative acceptance study. If a participant belongs to multiple constrained groups, record that overlap; do not quietly count one session as five independent observations for each segment.

| Segment; five sessions each | Tasks and observations | Results that would weaken or kill these hypotheses |
| --- | --- | --- |
| Newcomers using mobile at 390 pixels, including lower reading confidence | Explain the offer in their own words; find member sign-in; identify when operator sign-in applies. Record first interpretation, route, time, assistance and mistaken authority choice. | Consistently correct offer/role explanations and unaided sign-in discovery would weaken the public-page and role-handoff concerns. Agent completion cannot substitute for this comprehension test. |
| Keyboard and screen-reader developers at the compact layout | Find wallets, personal identity state and settings without pointer use; explain the menu's purpose before activation. Record navigation keys, detours and assistance separately from system loading time. | Unaided identification and operation of navigation weakens SD-03; correct predicted identity destination and direct navigation weakens SD-05. Independently assess accessible-name conformance even if skilled users succeed. |
| Returning developers using enlarged text and slow connections, including low-vision users | Encounter a safely simulated unavailable chain state, explain what still works, then find settings and read verification status. Record uncertainty and any abandonment before prompting. | Correctly scoped outage explanations and continued safe tasks weaken SD-01; readable status information without coaching weakens the service-impact part of SD-02. A successful task does not erase a measured contrast failure. |
| Interrupted node operators, including low-vision participants | Read readiness; distinguish unconfigured from stale providers; find the audit; explain the path from lost operator credentials to the deployer procedure. Use a scenario, never live private keys or configuration writes. | Correct freshness explanations weaken SD-04; a concrete, safe recovery handoff weakens SD-06. Merely reaching operator login is insufficient evidence. |

Permission denial and mid-task session expiry need a separate authorized scenario. Any tenant AI workflow authoring surface also needs a new scenario covering the draft-to-owner-review handoff, explanation of uncertainty and the effect of legal/tax warnings on decisions. No such surface or interaction was present in these pass-01 journeys, so this panel makes no claim about it.

## Limits and next-pass decision

Agents are patient, literate and unusually good at reading long explanations; that may hide public-page comprehension and settings-density problems. The visible-text mobile lane deliberately ignored icon recognition, which may inflate sign-in discovery effort. The zoom model changes CSS viewport and device scale rather than exercising a native browser zoom control. The keyboard path is one chosen sequence, not a lower bound on required navigation effort. No participant was distracted, used assistive technology live, configured a real node, or completed a service recovery.

Re-run the same goals against refreshed images while preserving pass-01 evidence and separating changed harness behavior from changed product behavior. Resolve the settings predicate timing issue before interpreting its next result. Do not declare the study passed or the service release-ready from this panel: two consecutive passing passes, functional authorization evidence and the separate owner live drill remain outside this lens's completed evidence.
